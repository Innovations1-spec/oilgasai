The Story

Built in the field.
Not on a whiteboard.

2021 – 2023
Field hardware deployment. Designed, built, and deployed the AMMMU — Autonomous Mobile Methane Measurement Unit — at Colorado State University's METEC facility. TGS2600/2611 MOx sensors, DHT22, Airmar PB200 weather station, Raspberry Pi / Phidgets SBC4 data logger, solar + LiFePO₄ power. Deployed alongside reference-grade Aeris MIRA laser analyzers in DOE-funded controlled-release experiments.
2024
ML calibration published. Developed a Random Forest regression pipeline correcting for temperature, humidity, cross-sensitivity, and baseline drift. Accuracy within ±0.8 ppm at 1.85–5.85 ppm vs. reference-grade instruments. Published in Atmosphere (MDPI, DOI: 10.3390/atmos15111313). 9 independent citations. DOE-funded, OSTI-indexed.

OilGasAI Model Alpha trained. Fine-tuned Llama 3.1 70B on 21,429 domain-specific instruction pairs using 10,000 GPU hours on CINECA's Leonardo HPC — allocated by UNDP AI Hub. QLoRA, 4-bit NF4, LoRA rank 64. RAG pipeline built with 37,009 EPA/PHMSA/OGMP 2.0 vectors. Training loss 1.90 → 1.08.

System Requirements
ℹ️ OilGasAI Model Alpha is a QLoRA adapter (1.6 GB) applied on top of the Meta Llama 3.1 70B Instruct base model. You must have access to Llama 3.1 70B separately. The adapter alone cannot run without the base model.
⚠️ A minimum of 40 GB GPU VRAM is required for 4-bit quantized inference (e.g., single NVIDIA A100 40GB, H100, or 2× A10G in multi-GPU mode). CPU inference is not recommended for production use.

03
Load the Model
ℹ️ OilGasAI Model Alpha ships as LoRA adapter weights. You load the base Llama 3.1 70B Instruct model first, then attach the OilGasAI adapter on top using PEFT's PeftModel.from_pretrained().
python
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig from peft import PeftModel import torch # Step 1: Configure 4-bit NF4 quantization # This reduces VRAM from ~140GB (bfloat16) to ~40GB bnb_config = BitsAndBytesConfig( load_in_4bit=True, bnb_4bit_quant_type="nf4", # Normal float 4 — best accuracy bnb_4bit_compute_dtype=torch.bfloat16, # Compute in bfloat16 bnb_4bit_use_double_quant=True # Nested quantization saves ~0.4 bits ) # Step 2: Load base model (Llama 3.1 70B Instruct) # Replace BASE_MODEL_PATH with your local path or HF repo ID BASE_MODEL_PATH = "meta-llama/Llama-3.1-70B-Instruct" base_model = AutoModelForCausalLM.from_pretrained( BASE_MODEL_PATH, quantization_config=bnb_config, device_map="auto", # Distributes across available GPUs trust_remote_code=True ) # Step 3: Load OilGasAI LoRA adapter # Replace ADAPTER_PATH with the path to the downloaded adapter weights ADAPTER_PATH = "./oilgasai-model-alpha-adapter" model = PeftModel.from_pretrained(base_model, ADAPTER_PATH) model.eval() # Set to inference mode # Step 4: Load tokenizer tokenizer = AutoTokenizer.from_pretrained(ADAPTER_PATH) tokenizer.pad_token = tokenizer.eos_token print("OilGasAI Model Alpha loaded successfully.")
04
Run Your First Query
OilGasAI Model Alpha uses the Llama 3.1 chat template. Always format queries as conversational messages rather than raw prompts.
python
def query_oilgasai(question: str, max_tokens: int = 512) -> str: """ Query OilGasAI Model Alpha with a domain-specific question. Args: question: Your oil and gas / emissions / compliance question max_tokens: Maximum response length (default: 512) Returns: Model response as a string """ messages = [ { "role": "user", "content": question } ] # Apply Llama 3.1 chat template text = tokenizer.apply_chat_template( messages, tokenize=False, add_generation_prompt=True ) inputs = tokenizer(text, return_tensors="pt").to(model.device) with torch.no_grad(): outputs = model.generate( **inputs, max_new_tokens=max_tokens, temperature=0.7, do_sample=True, pad_token_id=tokenizer.eos_token_id ) response = tokenizer.decode( outputs[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True ) return response # Example: EPA Subpart W compliance query response = query_oilgasai( "What are the EPA GHGRP Subpart W reporting thresholds for " "compressors at an onshore petroleum and natural gas production facility, " "and what calculation method should I use for centrifugal compressors?" ) print(response)
05
RAG Pipeline (Recommended for Production)
ℹ️ The built-in RAG pipeline provides document-grounded responses by retrieving relevant regulatory context before generating answers. This significantly improves accuracy on specific regulatory citations, emission factor values, and threshold numbers. Strongly recommended for any production or compliance workflow.
python
from sentence_transformers import SentenceTransformer import faiss import numpy as np import json # Load the pre-built FAISS index and document store # Index contains 37,009 vectors from EPA, PHMSA, NSPS, OGMP 2.0 documents embedding_model = SentenceTransformer("BAAI/bge-large-en-v1.5") index = faiss.read_index("./rag/faiss_index.bin") with open("./rag/document_store.json") as f: doc_store = json.load(f) # Maps vector IDs to source text + metadata def retrieve_context(query: str, top_k: int = 5) -> str: """Retrieve top-k relevant regulatory documents for a query.""" query_embedding = embedding_model.encode([query], normalize_embeddings=True) distances, indices = index.search(np.array(query_embedding), top_k) context_chunks = [] for idx in indices[0]: if idx != -1: # -1 means no result chunk = doc_store[str(idx)] context_chunks.append( f"[{chunk['source']}]\n{chunk['text']}" ) return "\n\n---\n\n".join(context_chunks) def query_with_rag(question: str) -> str: """Query OilGasAI with retrieved regulatory context.""" context = retrieve_context(question) augmented_prompt = f"""You are OilGasAI Model Alpha, a domain expert for oil and gas emissions compliance. Use the following regulatory context to answer the question accurately. REGULATORY CONTEXT: {context} QUESTION: {question} Provide a technically accurate response citing the relevant regulatory sections where applicable.""" messages = [{"role": "user", "content": augmented_prompt}] text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True) inputs = tokenizer(text, return_tensors="pt").to(model.device) with torch.no_grad(): outputs = model.generate(**inputs, max_new_tokens=768, temperature=0.7, do_sample=True) return tokenizer.decode(outputs[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)

Limitations & Professional Recommendations
⚠️ OilGasAI Model Alpha is an expert assistant, not an autonomous decision-maker. All regulatory submissions, safety-critical engineering calculations, and emissions compliance certifications must be reviewed and verified by a licensed professional engineer or qualified environmental compliance officer before submission to EPA, state agencies, or any regulatory body.
Specific limitations to be aware of in production use:
LimitationMitigation
Regulatory currency — Training data has a knowledge cutoff. Regulations, emission factors, and thresholds change. Always verify cited values against current EPA, state, and international regulatory documents before submission. Use RAG pipeline with updated document corpus.
Hallucination risk — Like all LLMs, the model may generate plausible but incorrect specific values (exact thresholds, deadlines, factor numbers). Cross-reference all specific numerical values against primary regulatory sources (ecfr.gov, EPA GHGRP technical support documents). Do not use model-generated numbers for final CDX submissions without verification.
U.S. regulatory bias — Training data is weighted toward U.S. EPA frameworks. International coverage (EU ETS, other national frameworks) is present but less extensive. For non-U.S. regulatory jurisdictions, supplement with jurisdiction-specific documents in the RAG pipeline.
Base model biases — Inherits biases from Llama 3.1 70B base model. Domain fine-tuning significantly reduces general LLM biases for this specific use case. Standard LLM evaluation practices apply.
